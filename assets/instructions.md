# Dossier Operating Instructions

How to drive the Dossier tools. What a Distilled State must contain is the Distillation Guide's job; these rules cover when and how to save, read, and resume.

- **On Resume:** Treat a recalled Distilled State as a briefing, not ground truth. Before acting: (1) check `## Current State`'s as-of stamp against reality—branch, commit, file contents, test status—and say what has drifted; (2) honour its working agreements (corrections, preferences, approval scopes) as if the user had just repeated them; (3) re-check `[assumed]` claims that the next step depends on; (4) follow `[src:]` pointers instead of guessing at what was compressed; (5) when the session start, `dossier_session`, or `dossier_recall` reports sessions that ended without saving, the state predates that work—say so to the user before acting on it. Do not reconstruct those sessions from their transcripts; if the user wants something specific from one, find it with `dossier_search` and fetch only that span. The notice clears with the next save that updates the Distilled State. Then take the first `## Next Steps` item, or confirm it with the user if the state is stale.
- **Poll Monitors:** Evaluate `(Last polled: date)` in `## Active Monitors`. Fetch updates solely if outdated. Distill findings; update timestamp.
- **References vs Monitors:** Use the shared line format `- [<kind>: <label>](<URL>) — <purpose or description>.` in both sections. `## References` is navigational and must not be polled; `## Active Monitors` carries the polling obligation and must include `(Last polled: YYYY-MM-DD)`. Do not duplicate a monitor in both sections. A URL alone is not evidence—capture fetched content as an artifact when it supports a claim.
- **Eager Saves:** Execute `dossier_save` immediately upon material decisions or milestones. End-of-session batching: [Rejected]. Rationale, load-bearing: the session-end and pre-compaction hooks run a binary, not an agent — they archive the transcript and **cannot distill on your behalf**. Nothing you did not save with `dossier_save` reaches the Distilled State. A session that saves only at the boundary saves nothing; the boundary reports that as a warning, after it is too late to act on. When the user runs `/save-dossier`, save then; if nothing material changed, say so in one line instead.
- **Save Content, Not Just Milestones:** Save as soon as the user corrects you, states a preference, or grants or limits an approval—that context exists only in the conversation and is the first thing a new session loses. Record it under `## Current State` (working agreements).
- **Concurrency:** Inject `base_revision` into `dossier_save`. Mitigates concurrent TUI overwrite conflicts. A stale base produces a `conflicts/*.md` artifact, never last-write-wins; surface it and resolve through `dossier_conflicts` / `dossier_resolve_conflict` with the user.
- **Protected Sections:** Routine saves may change Situation, Findings, Open Questions, Current State, Next Steps, Evidence, and Files. A change to Objective, Done When, Validation, Constraints, or Decisions goes in its own save, separate from routine updates; it is preserved as a whole-save `agent_proposal` conflict for human review, not applied. Tell the user it is waiting and ask them to accept or reject it.
- **Token Target:** Never truncate the Distilled State to fit `token_limit`. When a recall reports the Distilled State exceeds the token target, warn the user and propose consolidations; cutting signal is their call.
- **Ambiguous Targets:** When a link, merge, or bind target is ambiguous, ask the user. Never pick one silently.
- **Degrade Visibly:** When a capability is missing—transcript capture, a lifecycle hook, the Guide itself—say so to the user. Never proceed as if it worked.
- **Artifacts:** Pass raw logs/transcripts as structured artifacts via `dossier_save`. Hand-written files into `<slug>/artifacts/`: [Rejected] — that namespace is frontmatter-only and a loose file there is silently discarded (see **Working Files**). Prefer small, purpose-built artifacts (`decision_evidence`, `file_snapshot`, `query`, `link`) captured when the evidence appears, over one coarse end-of-session `transcript`.
- **Resolve Citations:** `dossier_artifact` fetches a cited artifact, or a cited span via `fragment: "L42-L68"`. Follow a `[src:]` pointer instead of guessing at what was compressed away, and instead of re-deriving what a past session already established.
- **Read the Archive in Spans:** The Distilled State is what you load; the Archive is consulted, never reloaded. An unranged `dossier_artifact` on a large artifact returns its outline and line count instead of its content—pick the range you need from that. Pass `full: true` only when the user asks for the whole artifact or the task genuinely needs all of it.
- **Evidence Index:** `dossier_recall` returns `artifacts[]` (type, line count, cited/uncited) and `dossier_artifacts` lists it directly. An uncited-artifact warning means the distilled state has drifted off its own record: cite it or state why it is immaterial, judging from its title, type, and targeted spans rather than reading it whole.
- **Cite Spans, Not Blobs:** Write `[src:art_<id>#L<a>-L<b>]` when the claim comes from part of a source. Ranges are validated against the artifact by `dossier doctor`.
- **Working Files:** Default loose deliverables, scratch files, and user-provided attachments to `<dossier_home>/<slug>/files/` (`<dossier_home>/archive/<slug>/files/` once the dossier is done) (direct filesystem write) to keep the dossier portable. Never `<slug>/artifacts/`: that namespace is parsed, not scanned — a file without artifact frontmatter is skipped by the evidence index, carries no `art_` id to cite, and never enters the revision hash, while still surfacing in `dossier_search`. It reads as captured evidence while being none. Promote a working file to real evidence with `dossier link --from-file` (or a `dossier_save` artifact), which mints the id, provenance, and line count that `[src:]` resolves against. Does not apply to work that belongs to a repo the Dossier lists (its `repos`): project work (code, docs, assets the repo keeps) goes in the repo under the repo's own CLAUDE.md/AGENTS.md. Explicit user-specified path: overrides default. Every file you create (in `files/`, in a repo, or at a user-specified path) must be listed under `## Files` in the Distilled State via `dossier_save`, so it can be found next session. Record repo files as `<repo identity>:<path relative to the repo>` (e.g. `github.com/acme/api:docs/plan.md`), never as an absolute path — a shared Dossier is read on machines where your paths don't exist. Record other files outside the Dossier directory by full path.
- **Canonical Work Brief:** The Dossier is the single source of truth for Objective, Done When, Validation, Constraints, and, when several contributions combine into one outcome, Deliverables. Do not duplicate those fields in a delegation contract or outbound-note store. A `spark` may remain loose; use `define` to shape the brief before work enters `execute`.
- **Constraints Are Signal:** Retain every boundary that changes the feasible solution space—technical, commercial, legal, timing, budget, dependency, interface, or authority. Tag assumptions; name the decision-maker or relief path for constraints a leader can alleviate. Never silently drop a constraint to make a solution fit; record its removal or change as a Decision with provenance.
- **Definition Checkpoint:** Before moving a Dossier from `define` to `execute`, and before delegating any scope, ask whether the person doing it can proceed and know when they are finished. Name concrete gaps; never use a completeness score. Single-deliverable Dossiers use the top-level Objective / Done When / Validation. Multi-deliverable Dossiers give every deliverable its own local Done When and Validation.
- **Delegation:** Use delegation to assess and improve the canonical Dossier. Store only Scope, Acceptance, Decision Rights, Escalation, and Return Expectations under `## Delegation Contracts`; the rendered note pulls work truth from the Dossier. Record the accepted revision and surface material goalpost drift before checking completion.
- **Handoff:** Commit active-work checkpoints via `dossier_save`, including current `status` and the concise `next_action` baton. Keep supporting detail in `## Current State` / `## Next Steps`. Use `dossier_update` for isolated metadata mutations.
